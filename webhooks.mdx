## Overview

TikTool can POST JSON events to your own HTTPS endpoint when a watched creator goes live, ends a stream, hits a viewer peak, receives a high-value gift, or crosses a follower milestone. Every delivery is HMAC-SHA256-signed, retried on failure, and replayable from the dashboard.

<Note>
Webhooks are available on **every paid plan** (Basic, Pro, Ultra, Agency). Webhook deliveries do **not** count against your API request quota.
</Note>

## Create a webhook

Webhooks are configured in the dashboard, not over the REST API. There is no `/webcast/webhooks` endpoint - the `/webcast/` host serves live-data calls only, so requests there return a 404 by design.

Dashboard → **Webhooks** → **New webhook** (at [tik.tools/webhooks](https://tik.tools/webhooks))

Fields:

- **Target URL** — must be HTTPS. Cannot point to private networks.
- **Events** — pick from the available types for your tier.
- **Creators** — one handle per line, e.g. `charlidamelio`. Leave empty to receive events for **all** creators on your watchlist.
- **Bearer token** (optional) — sent as `Authorization: Bearer <token>` alongside the HMAC signature.

After creating, your **webhook secret** (format `whsec_<32-byte base64url>`) is shown **once**. Save it — it cannot be retrieved later. Use **Rotate secret** to generate a new one (invalidates the old immediately).

## Verifying the signature

Always verify `X-Tiktool-Signature` before processing the payload. The header has the form `t=<unix_ts>,v1=<hex_hmac>`. Compute `HMAC-SHA256(your_secret, "<ts>.<raw_body>")` and constant-time-compare to `v1`.

Reject any request where `|now - ts| > 300` seconds (replay protection).

### Node / Bun

```js
import crypto from 'node:crypto'

const SECRET = process.env.TIKTOOL_WEBHOOK_SECRET

export async function POST(req) {
  const raw = await req.text()
  const sig = req.headers.get('x-tiktool-signature') || ''
  const parts = Object.fromEntries(sig.split(',').map(p => p.split('=', 2)))
  const ts = Number(parts.t)
  const v1 = parts.v1

  if (!ts || !v1) return new Response('bad signature', { status: 400 })
  if (Math.abs(Math.floor(Date.now() / 1000) - ts) > 300) {
    return new Response('stale', { status: 400 })
  }

  const expected = crypto.createHmac('sha256', SECRET).update(`${ts}.${raw}`).digest('hex')
  if (!crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(v1))) {
    return new Response('invalid signature', { status: 401 })
  }

  const event = JSON.parse(raw)
  // event.event_id is stable across retries - use it as your idempotency key
  // ...handle event
  return new Response('ok')
}
```

### Supabase Edge Function (Deno)

```ts
import { createHmac, timingSafeEqual } from 'node:crypto'

Deno.serve(async (req) => {
  const raw = await req.text()
  const sig = req.headers.get('x-tiktool-signature') ?? ''
  const t = Number(sig.match(/t=(\d+)/)?.[1])
  const v1 = sig.match(/v1=([a-f0-9]+)/)?.[1]
  if (!t || !v1) return new Response('bad sig', { status: 400 })

  const secret = Deno.env.get('TIKTOOL_WEBHOOK_SECRET')!
  const expected = createHmac('sha256', secret).update(`${t}.${raw}`).digest('hex')
  if (!timingSafeEqual(Buffer.from(expected), Buffer.from(v1))) {
    return new Response('invalid sig', { status: 401 })
  }
  if (Math.abs(Math.floor(Date.now() / 1000) - t) > 300) {
    return new Response('stale', { status: 400 })
  }

  const evt = JSON.parse(raw)
  // ...handle event
  return new Response('ok')
})
```

### Python (FastAPI)

```python
import hmac, hashlib, time
from fastapi import FastAPI, Request, HTTPException

app = FastAPI()
SECRET = "whsec_..."

@app.post("/tiktok-live")
async def tiktok_live(req: Request):
    raw = (await req.body()).decode()
    sig = req.headers.get("x-tiktool-signature", "")
    parts = dict(p.split("=", 1) for p in sig.split(","))
    ts = int(parts.get("t", "0"))
    v1 = parts.get("v1", "")
    if not ts or not v1:
        raise HTTPException(400, "bad signature")
    if abs(int(time.time()) - ts) > 300:
        raise HTTPException(400, "stale")
    expected = hmac.new(SECRET.encode(), f"{ts}.{raw}".encode(), hashlib.sha256).hexdigest()
    if not hmac.compare_digest(expected, v1):
        raise HTTPException(401, "invalid signature")
    evt = json.loads(raw)
    # ...handle
    return {"ok": True}
```

## Idempotency

`event_id` is **stable across retries** of the same event. Use it as your idempotency key.

`delivery_id` is **unique per attempt** (a retry of the same `event_id` gets a fresh `delivery_id`). Useful for tracing in our delivery log.

If your endpoint processes an event successfully but fails to respond `2xx` (e.g. you crashed after the database insert), TikTool will retry, and the duplicate delivery will hit your endpoint again with the same `event_id`. Dedupe on it.

## Retry policy

If your endpoint returns anything other than a `2xx` status — or times out (connect timeout 10s, read timeout 15s) — TikTool retries on this schedule:

```
attempt 1: immediate
attempt 2: +30 seconds
attempt 3: +2 minutes
attempt 4: +10 minutes
attempt 5: +1 hour
attempt 6: +6 hours
```

After **6 attempts** over ~7 hours, the event is marked **dead-letter**. You can replay any failed delivery manually from the dashboard for 7 days.

If a webhook has **50 consecutive dead-letter events**, it is automatically disabled. We'll email you (and you'll see the disabled status on the dashboard). Re-enable from the dashboard once your endpoint is healthy.

## Quotas

Daily delivery quotas are tracked per user, per UTC day:

- **Ultra:** 10,000 deliveries/day
- **Agency:** 100,000 deliveries/day

Deliveries that exceed the quota are dropped (not queued) and surfaced as `quota_exceeded` in your dashboard. Upgrade to raise the limit.

## Best practices

- **Respond fast.** Acknowledge with `200` within 5 seconds. Do heavy work async after responding.
- **Idempotency key = `event_id`.** Always.
- **Verify the signature.** No exceptions.
- **Don't trust the timestamp from the payload alone** — use the `X-Tiktool-Timestamp` header inside HMAC verification to prevent replay attacks beyond the 5-minute window.
- **Avoid 3xx redirects.** We do not follow redirects. Configure your endpoint as the final URL.
- **Logs.** We retain raw request bodies for 30 days in ClickHouse — request a CSV export from support if you need an audit trail.

## Errors

| Behavior | Reason |
|---|---|
| 401 from your endpoint | Check `X-Tiktool-Signature` verification logic |
| Auto-disabled | 50 consecutive dead-letters; fix endpoint then re-enable |
| `quota_exceeded` | Daily delivery cap reached; upgrade or wait for UTC midnight reset |
| Missing `live.end` | Your endpoint must have been responsive within the 7-hour retry window |

## Migration / coming-from-other-tools

If you currently use Discord/Telegram alerts via TikTool, those continue to work alongside webhooks. The two channels are independent — adding a webhook does not affect existing alerts.
