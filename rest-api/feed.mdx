## `GET` `/webcast/feed`

Discover currently live TikTok LIVE streams. This is a two-step discovery helper: the API returns a ready-to-run request (`signed_url`, `method`, `headers`, `cookies`), and you execute that request from your own client to get a page of live rooms. This is the recommended way to discover LIVE rooms.

**Authentication:** send your API key in the `x-api-key` header (or the `apiKey` query parameter).

**Personalized results (optional):** send your own TikTok session token in the `x-tiktok-session` header (or `session_id` in a POST body) for fuller, personalized pages. Without it, results are anonymous and limited (around 5 rooms). Prefer the header so the value never appears in a URL.

**Channels:** `87` = Recommended "For You" feed (default), `86` = Suggested hosts, `89` or `1111006` = Gaming, `42` = Following (requires a session).

**Geo-targeting:** results follow the location of the client that executes the returned request (step 2), not the `region` parameter. Run step 2 from the market you want to discover.

**Pagination:** each page returns roughly 6-15 rooms. Read `extra.max_time` from the page you received and pass it as `max_time` on your next call. The response also includes a `load_more_url` template; replace `{MAX_TIME}` with the cursor.

**Rate limits:** Pro: 100 calls/day. Ultra: 2,000 calls/day. Every response includes `feed_remaining` and `feed_limit`. When the daily quota is used up the API returns an error with a `message`; the quota resets daily (see [Rate Limits](/reference/rate-limits)).

**Room data:** each room includes `id_str` (room ID), `title`, `user_count` (viewers), `owner.display_id` (username), `owner.nickname` (display name), `owner.avatar_thumb` (profile photo) and more.

<Note>
This endpoint requires a **Pro** tier subscription or higher.
</Note>

### Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `channel_id` | string | No | Feed channel: 87 = Recommended "For You" (default), 86 = Suggested, 89 or 1111006 = Gaming, 42 = Following |
| `count` | number | No | Rooms per page (default: 20, max: 50) |
| `max_time` | string | No | Pagination cursor from the previous page (`extra.max_time`). Omit or `"0"` for the first page. |
| `region` | string | No | Region hint (default: US). Results are geo-targeted by the client that runs step 2. |
| `session_id` | string | No | Your own TikTok session token for personalized results. Prefer the `x-tiktok-session` header, which keeps it out of URLs. |

### Response

```json
{
  "status_code": 0,
  "signed_url": "https://...",
  "method": "GET",
  "headers": { "User-Agent": "...", ... },
  "cookies": "...",
  "region": "US",
  "channel_id": "87",
  "feed_remaining": 99,
  "feed_limit": 100,
  "note": "Execute signed_url from your client with these headers."
}

// Executing the returned request gives a page of rooms:
{
  "status_code": 0,
  "data": [{
    "data": {
      "id_str": "7123456789",
      "title": "Live Now!",
      "user_count": 1250,
      "owner": {
        "display_id": "streamer_name",
        "nickname": "Display Name",
        "avatar_thumb": { "url_list": ["https://..."] }
      }
    }
  }, ...],
  "extra": { "max_time": "1773128824428" }
}
```

Send the returned `headers` and the `cookies` value exactly as given (as the `Cookie` header). Treat all returned values as opaque and short-lived.

### Examples

<CodeGroup>
````javascript Node.js
// Step 1: Get a ready-to-run request. Key and session go in headers.
const auth = { 'x-api-key': 'YOUR_KEY', 'x-tiktok-session': 'YOUR_SESSION' };
const res = await fetch(
  'https://api.tik.tools/webcast/feed?' + new URLSearchParams({
    region: 'US',
    channel_id: '87',  // 87=recommended, 86=suggested, 1111006=gaming
    count: '20',
  }),
  { headers: auth }
);
const { signed_url, headers, cookies, feed_remaining, feed_limit } = await res.json();
console.log(`Quota: ${feed_remaining}/${feed_limit} calls remaining`);

// Step 2: Execute it from your own client
const pageRes = await fetch(signed_url, {
  headers: { ...headers, Cookie: cookies }
});
const feed = await pageRes.json();

// Step 3: Read live rooms
for (const entry of feed.data) {
  const room = entry.data;
  console.log(`@${room.owner.display_id} (${room.owner.nickname})`);
  console.log(`   "${room.title}" - ${room.user_count} viewers`);
}

// Step 4: Next page
const nextCursor = feed.extra?.max_time;
if (nextCursor) {
  const page2 = await fetch(
    'https://api.tik.tools/webcast/feed?' + new URLSearchParams({
      region: 'US', max_time: nextCursor, count: '20',
    }),
    { headers: auth }
  );
  // ... repeat steps 2-3
}
````

```python Python
import requests

# Step 1: Get a ready-to-run request. Key and session go in headers.
auth = {'x-api-key': 'YOUR_KEY', 'x-tiktok-session': 'YOUR_SESSION'}
res = requests.get('https://api.tik.tools/webcast/feed', headers=auth, params={
    'region': 'US',
    'channel_id': '87',
    'count': 20,
})
info = res.json()
print(f"Quota: {info['feed_remaining']}/{info['feed_limit']}")

# Step 2: Execute it from your own client
headers = {**info['headers'], 'Cookie': info.get('cookies', '')}
page = requests.get(info['signed_url'], headers=headers).json()

# Step 3: Read live rooms
for entry in page.get('data', []):
    room = entry['data']
    owner = room['owner']
    print(f"@{owner['display_id']}: \"{room['title']}\" - {room['user_count']} viewers")

# Step 4: Next page
cursor = page.get('extra', {}).get('max_time')
if cursor:
    next_info = requests.get('https://api.tik.tools/webcast/feed', headers=auth, params={
        'region': 'US', 'max_time': cursor,
    }).json()
    # ... repeat steps 2-3
```
